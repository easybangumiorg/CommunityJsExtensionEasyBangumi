GGL Beta 使用独立 key，不覆盖正式 GGL。MiFun 的新入口与原站关系经站点自身配置确认，保留 key；搜索分页返回 API15 要求的整数，只跟随站点实际下一页地址，并绑定当前 Host 和关键词。次元城改用新版 API，新作品 ID 使用 `cyc-v2:`，旧数值 ID 不直接映射到新版同号作品。MiliMili 按服务返回的 `nextOffset` 翻页，搜索接口没有游标，因此不伪造搜索分页；剧集按实际 `sortOrder` 排列。

## Host 修改约定

五个源都提供 `Host`，接受留空恢复默认、无协议域名补 `https://`，剔除查询参数、片段及末尾斜杠，拒绝无效地址、账号密码和非 HTTP(S) 协议。请求、Referer、作品网页地址与同站相对图片随 Host 更新；站点返回的外部 CDN 地址保持原样。作品与剧集 ID 不嵌入新 Host；改 Host 后不能继续使用旧 Host 的分页上下文。

GGL Beta 的网页与公共 API 是两个不同服务，因此额外提供 `ApiHost`；修改网页 Host 不猜测 API 域名。Host 能解决同契约入口迁移，不能把无关网站转成兼容源。旧收藏只有在识别路由并核对作品后才兼容，避免仅凭数字 ID 关联错作品。

## 真机流程与证据

设备为小米 14（23127PN0CC，Android 16/API36，物理序列号 `6a022def`），使用独立 `.sourcelab` 包。无线端点会变化，每次执行前重新发现并核对设备身份；不把 IP:端口当作固定设备序列号。原始报告与机器摘要在 [本批记录](../acceptance/new-sites-2026-10-14.json)。

1. 输入最终 JS 文件，记录 key、版本、SHA256、客户端构建、设备、网络及环境。
2. 检查首页第一有效页；依次搜索 `孤独摇滚`、`孤獨搖滾`、`ぼっち・ざ・ろっく！`、`Bocchi the Rock`。只有无结果才换词，搜索错误与空结果分别记录。
3. 选第一次命中的结果第一部，读取详情与全部线路；每条线路尝试第一集，直到实际播放成功。不能换另一部作品替代失败；都无结果时才尝试首页第一部，并保留降级路径。
4. 真实播放器必须取得非零尺寸首帧，正常进度推进至少 3000ms。地址解析成功、HTTP200、媒体探测通过均不代替播放通过。
5. 遇到验证码保留原窗口，用户完成后点击“验证完成，重试”，继续同一作品/剧集。人工等待独立计时，可跳过当前源。用户已说明没有账号的站点不重复要求登录，记为登录后待验证。
6. 新失败、锁屏导致的界面初始化失败与重测成功分开保留。源改字节必须更新 hash；未对应最终字节的旧报告不能授权晋级 release。

首轮 GGL Beta 因锁屏没有取得播放画面窗口，属于测试界面初始化失败；用户解锁后重测通过，两个原件并存。后续无线 ADB 一度离线；用户恢复后通过 mDNS 发现新端口 `45693` 并核对同一物理序列号。路漫漫正常验证、取证和最终整链验收完成；Omoo 独立单页请求仍只取得空白文档，不误报搜索零结果。

这批早期报告的 `context.device.serial` 误填为无线 ADB 端点。原件保持不变，另存已核对物理设备的连接记录；Android 脚本现改读 `ro.serialno` / `ro.boot.serialno`，并分开保存 `adbTarget`。7 项脚本单测通过，最终五源真机报告均已正确记录物理序列号。

最终复核修复了未使用的 Blob 钩子干扰、无效成功响应被当作空结果、验证回调误取其它剧集的历史媒体、搜索关键词未绑定和读取 SDK 不存在的 `summary.title` 等边界。MiliMili、MiFun、次元城、GGL Beta 的早期报告按旧 hash 保留；当前五个源的最终 hash 都有匹配的真机报告。播放回调核对原 Host 与当前作品/线路/集数，只读取当前播放器；不从历史资源表认定当前集可播。
